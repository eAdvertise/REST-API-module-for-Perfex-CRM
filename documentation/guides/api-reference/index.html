eAD-CRM REST API Documentation

An original, self-contained guide for the API and API-V3 modules, including Guest Invoice Checkout and extension points for future endpoints.

Base URL: https://your-domain.example/api   Format: JSON   API version: 3.0.3

Authentication

Create an API user/token in the CRM API management screen and grant only the required capabilities. Send the token with every protected request.

curl "https://your-domain.example/api/customers" \
  -H "authtoken: YOUR_API_TOKEN" \
  -H "Accept: application/json"
Important: use the authtoken header. Never place production tokens in URLs, JavaScript bundles, screenshots, repositories or documentation examples.

Requests, responses and pagination

Write endpoints accept JSON and, where supported, form data. Use Content-Type: application/json. Collection endpoints may support page, per_page, sort, field selection and date filters depending on the resource.

curl -X POST "https://your-domain.example/api/leads" \
  -H "authtoken: YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Example Lead","email":"lead@example.com","source":1,"status":1}'

Guest Invoices / Checkout

POST/api/guest_invoices

Create or reuse a guest contact by email and create an invoice.

POST/api/guest_invoices/checkout

Create/reuse guest, create invoice, record payment and optionally send invoice and receipt PDFs in one email.

POST/api/guestinvoices/checkout

Legacy alias for checkout.

Production checklist

  • Use HTTPS only.
  • Create separate least-privilege tokens per integration.
  • Rotate exposed tokens immediately.
  • Do not commit SQL dumps, credentials or real payloads.
  • Validate webhook signatures and use idempotency keys for retried writes.
  • Log correlation ids, not secrets or full payment data.
  • Test migrations and API writes on staging before production.

Adding future endpoints

  1. Add controller and explicit routes before generic routes.
  2. Register token capabilities.
  3. Add OpenAPI schemas and paths.
  4. Add safe examples here without production data.
  5. Add validation, migration and compatibility tests.
