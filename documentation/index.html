eAD-CRM API Guide

Our own API documentation hub for the REST API module. It keeps the familiar structure of the existing guide, removes vendor/license onboarding, and gives us a clear place to document Guest Invoice checkout plus every new endpoint we add later.

Base URL
https://your-domain.com/api
Auth
authtoken: YOUR_API_TOKEN
Formats
JSON or multipart/form-data

Authentication

Every protected endpoint expects an API token in the authtoken header. Create and scope tokens from the API management area, then grant only the resources/capabilities the integration needs.

curl -X GET "https://your-domain.com/api/customers" \
  -H "authtoken: YOUR_API_TOKEN" \
  -H "Accept: application/json"
This fork does not require external vendor activation. API access is controlled by eAD-CRM users, API tokens and permissions.

Requests & responses

Write endpoints accept JSON payloads and legacy form-data payloads. Responses are JSON. Some legacy list endpoints return a plain array when no pagination parameters are present; paginated calls return a {data, meta} envelope.

{
  "data": [],
  "meta": {
    "page": 1,
    "per_page": 25,
    "total": 0,
    "total_pages": 0,
    "has_more": false
  }
}

Pagination, sorting, field selection and date filters

ParameterPurpose
page1-based page number; enables the paginated response envelope.
per_pageRows per page. Use sensible page sizes for large CRM datasets.
sortComma-separated columns; prefix a column with - for descending order.
fieldsComma-separated response fields when a controller supports projection.
created_after, created_beforeISO date bounds for resources with a date column.
curl "https://your-domain.com/api/invoices?page=1&per_page=25&sort=-date&fields=id,number,total,status" \
  -H "authtoken: YOUR_API_TOKEN"

Errors

Validation failures return JSON with a status flag, message and optional field-level errors. Missing permissions or missing records return an error object with the relevant HTTP status.

{
  "status": false,
  "message": "Validation failed",
  "errors": {
    "email": "The email field is required."
  }
}

Guest Invoices / Checkout

The Guest Invoice flow creates or reuses a guest customer/contact by email, creates an invoice, optionally records a payment, and can send a single email with invoice and receipt PDFs.

POST/api/guest_invoices

Create/reuse guest + create invoice.

POST/api/guest_invoices/checkout

Create/reuse guest + invoice + payment, with optional email attachments.

Minimal checkout payload

{
  "email": "guest@example.com",
  "name": "Guest Customer",
  "payment_mode": 1,
  "send_email": true,
  "items": [
    {
      "description": "Online order #1001",
      "long_description": "Guest checkout order",
      "qty": 1,
      "rate": 49.90,
      "taxname": ["VAT|24.00"]
    }
  ],
  "transaction_id": "web-1001"
}
FieldRequiredNotes
emailYesPrimary lookup key for the guest contact.
itemsYesArray of invoice items. Each item should include description, quantity and rate.
payment_modeCheckout onlyPayment mode id used when recording the payment.
send_emailNoWhen true, sends the editable Guest Checkout email template with invoice and receipt PDFs where available.
company, address fields, phoneNoUsed when creating the guest client or enriching existing data.
curl -X POST "https://your-domain.com/api/guest_invoices/checkout" \
  -H "authtoken: YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d @guest-checkout.json

Core CRM resources

The REST module exposes standard CRUD-style routes for the main CRM resources. Most resources support GET /{resource}, POST /{resource}, GET /{resource}/{id}, PUT /{resource}/{id}, DELETE /{resource}/{id} and GET /{resource}/search/{keyword}.

Sales
Invoices, estimates, proposals, credit notes, payments, payment modes, taxes, subscriptions.
CRM
Customers, contacts, leads, staff, calendar events, notes, custom fields.
Work
Projects, tasks, milestones, timesheets, tickets, contracts, expenses, items, knowledge base.

Standard route pattern

GET/api/{resource}
POST/api/{resource}
GET/api/{resource}/{id}
PUT/api/{resource}/{id}
DELETE/api/{resource}/{id}

Common lookups

Use lookup endpoints/tools for ids that are needed by write payloads: countries, currencies, taxes, payment modes, expense categories, lead sources/statuses and departments.

Automation, MCP and webhooks

Automation endpoints include batch-style integrations, webhook management and the MCP JSON-RPC server for AI agents. The MCP surface is permission-filtered so a token only exposes tools it can actually call.

POST/api/mcp

JSON-RPC endpoint for initialize, ping, tools/list and tools/call.

GET/api/webhooks/events

Event catalog for webhook subscriptions.

OpenAPI, Swagger UI and generated clients

The machine-readable contract is available at /api/openapi.json. Use Swagger UI from the module, import the spec into Postman/Insomnia, or generate integration clients from the same source.

curl "https://your-domain.com/api/openapi.json" -H "Accept: application/json"
