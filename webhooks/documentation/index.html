Webhooks 2.0

Connect eAD-CRM to any HTTP service

Configure event-driven HTTP requests for core CRM records and optional modules, with custom headers, payload mappings, delays, delivery logs and retry diagnostics.

Use staging first. A webhook can transmit customer and financial data to an external system. Test the destination, authentication and payload before enabling production events.

Architecture

How delivery works

eAD-CRM eventCreate, edit, delete, status or module event
→
WebhooksFilter, enrich and map payload
→
Queue / HTTPImmediate or scheduled request
→
Your serviceAPI, automation, ERP or middleware

Only active webhooks matching both the selected resource and action are delivered. Delayed webhooks are stored in the queue and require the Webhooks cron.

Configuration

Create a webhook

  1. Open Webhooks → Webhooks and select New Webhook.
  2. Enter a descriptive name.
  3. Select Webhook For; optional modules appear only when installed.
  4. Select one or more actions.
  5. Configure the destination URL, method and format.
  6. Add authentication headers and custom body fields.
  7. Use Test Webhook, then save and enable it.
Recommended: create separate webhooks per destination and business purpose. This makes failures, rotation and auditing easier.

Resources and actions

Core resources include leads, contacts/clients, invoices, tasks, projects, proposals, tickets, payments, staff, contracts, estimates, calendar events, expenses, credit notes and items.

ActionMeaning
addRecord created
editRecord updated
deleteRecord is being or has been deleted
status_changeApproval, cancellation or another lifecycle transition
sentEmail/document successfully sent
converted_to_invoiceSource document converted to an invoice

Request URL, method and format

HTTPGET · POST · PUT · PATCH · DELETE
  • Request URL: use HTTPS and a stable endpoint.
  • Format JSON: POST/PATCH/PUT bodies are JSON encoded.
  • Format FORM: fields are sent as form data.
  • GET and DELETE requests are delivered without a JSON body.
POST https://automation.example.com/hooks/eadcrm
Content-Type: application/json
Authorization: Bearer YOUR_SECRET

Headers, body fields and merge values

Add standard or custom headers. Add body key/value pairs to supplement the full record payload. Type @ in a mentionable value field to select available merge fields.

Authorization: Bearer @{custom_token}
X-Source: eadcrm

body[event_source] = eadcrm
body[customer_name] = @{client_company}
Never place passwords or long-lived secrets in query strings. Prefer an Authorization header and rotate it periodically.

Delayed delivery and cron

Set Trigger after to queue delivery by minutes, hours or days. Configure the Webhooks cron shown under Settings → Webhooks. Pending jobs remain in scheduled_webhooks until the cron executes them.

*/5 * * * * php /path/to/perfex/index.php webhooks/cron/index

Use the exact command displayed by your installation; paths and PHP binaries differ by server.

Operations

Security checklist

  • Always use HTTPS.
  • Authenticate requests with a secret header or signature validated by the receiver.
  • Allowlist egress IPs where practical.
  • Send only required data and review custom fields for personal information.
  • Return a 2xx response quickly; process heavy work asynchronously.
  • Rotate secrets and disable unused webhooks.

Safe test plan

  1. Use a request inspector or staging endpoint.
  2. Create the webhook with debug mode enabled.
  3. Click Test Webhook and confirm method, headers and body.
  4. Create a test CRM record and confirm one delivery.
  5. Test update/status/delete separately.
  6. Force a 401 and 500 to verify logs and alerts.
  7. For delayed delivery, confirm PENDING → SUCCESS after cron.
  8. Disable debug mode after validation.

Troubleshooting

SymptomCheck
No request arrivesWebhook active, correct resource/action, destination DNS/firewall and module installed.
401/403Authorization header, secret rotation and receiver permissions.
400/422JSON/form choice, required fields, value types and merge-field output.
Jobs stay pendingWebhooks cron command, PHP path, file permissions and server cron logs.
Duplicate processingMake the receiver idempotent using resource ID plus action/event name.
Optional module missingConfirm its folder is installed and the module is loaded; refresh the form.
